# Track: DB / Table Design

## Outcome

要件文を渡されたら、30分でER図・DDL・制約・想定クエリまで書き、正規化と整合性の判断を説明できる。

## Topic map

| Area | L1 | L2（現在） | L3 |
|---|---|---|---|
| 正規化 | 第1〜3正規形の定義 | 要件から3NFへ落とす | 意図的な非正規化とその代償 |
| キー設計 | 主キーと外部キー | 自然キー vs 代理キー | 分散環境でのID戦略 |
| 制約 | NOT NULL / UNIQUE | 複合一意制約で不正状態を防ぐ | 除外制約・チェック制約の活用 |
| インデックス | B-treeの基本 | 複合インデックスの列順 | カバリング・部分インデックス |
| トランザクション | ACIDの意味 | 分離レベルと発生する異常 | 楽観/悲観ロックの選択 |
| 履歴・時間 | created_at / updated_at | 論理削除と有効期間の表現 | 監査ログとイベントソーシング |
| マイグレーション | カラム追加 | 無停止でのスキーマ変更 | 大規模テーブルの分割 |

## Recurring question forms

- 与えられた要件のテーブル設計とDDLを書く
- 与えられたスキーマの問題点を3つ指摘し修正する
- 重複・二重登録を防ぐ制約を設計する
- 特定クエリを速くするインデックスを設計し、理由を述べる
- 遅いクエリの原因仮説を3つ挙げ、確認手順を書く

## Retest triggers

- 分離レベルの選択根拠が言えなかった
- 複合インデックスの列順の基準が言えなかった
- 論理削除と一意制約の衝突を説明できなかった
