# Track: Layered Architecture

## Outcome

ユースケースを渡されたら、レイヤー分割・依存方向・各層の責務を図と文章で示し、なぜその境界にしたかを説明できる。

## Topic map

| Area | L1 | L2（現在） | L3 |
|---|---|---|---|
| レイヤー分割 | 3層の役割 | Presentation / Application / Domain / Infrastructureの責務 | 境界の再設計とモジュール分割 |
| 依存方向 | 上から下への依存 | 依存性逆転が必要な箇所を特定する | ポート/アダプタの設計 |
| ドメインモデル | エンティティと値オブジェクト | 不変条件をモデル内に閉じる | 集約境界とトランザクション境界の一致 |
| ユースケース | サービスクラスの責務 | アプリケーション層の入出力を定義する | ユースケース間の再利用と分割 |
| 横断関心 | ログ・認証の置き場所 | 各層のどこに置くか判断する | 横断関心の注入方式の比較 |
| ドキュメント | 設計メモ | 判断理由を残す | ADRを書き、選択肢と代償を残す |

## Recurring question forms

- 与えられたユースケースをレイヤー分割し、依存方向を図示する
- 与えられたコードの依存方向違反を指摘し、修正案を出す
- ドメインロジックがどの層にあるべきか判断し、理由を述べる
- 2つの設計案を比較し、条件付きでどちらを選ぶかADR形式で書く

## Retest triggers

- ドメイン層がインフラ層に依存していることに気づけなかった
- 依存性逆転の必要性を説明できなかった
- 集約境界とトランザクション境界を関連付けられなかった
