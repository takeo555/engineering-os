# Track: Network / Infra

## Outcome

「繋がらない」「遅い」を上位レイヤーから順に切り分け、確認コマンドと期待結果を並べた手順を書ける。

## Topic map

| Area | L1 | L2（現在） | L3 |
|---|---|---|---|
| TCP/IP | レイヤーの役割 | 3-way handshakeとタイムアウトの読み方 | 輻輳制御とチューニング |
| DNS | 名前解決の流れ | TTLとキャッシュに起因する事象 | 切替時の設計 |
| TLS | HTTPSの目的 | 証明書検証の失敗パターン | 終端位置の設計 |
| ロードバランサ | 役割 | ヘルスチェックとセッション | 接続維持とドレイン |
| 可用性 | 冗長化の意味 | 単一障害点を特定する | 目標復旧時間からの設計 |
| 観測 | ログを見る | メトリクスから遅延の所在を絞る | 分散トレースの設計 |
| 切り分け | pingとcurl | レイヤー順の手順を組む | 再現条件の特定 |

## Recurring question forms

- 症状を渡され、切り分け手順を上位レイヤーから書く
- 「一部ユーザーだけ遅い」の原因候補を5つ挙げ、確認方法を書く
- 与えられた構成図の単一障害点を指摘する
- ブラウザにURLを入れてから表示までを順に説明する
- タイムアウト値をどこに何秒で設定するか根拠付きで決める

## Retest triggers

- DNSのTTLに起因する事象を切り分け候補に挙げられなかった
- タイムアウトの設定箇所を整理できなかった
- ヘルスチェック失敗時の挙動を説明できなかった
