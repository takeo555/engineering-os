# Track: Coding / Go / Next.js

## Outcome

小さな機能を Go または Next.js で動かし、置き場所（handler / usecase、またはページ / データ取得）を根拠付きで説明できる。文法を一通り終えることが到達点ではない。

## Topic map

| Area | L1 | L2 | L3 |
|---|---|---|---|
| Go の骨格 | パッケージと関数、エラーを返す | handler と usecase を分ける | インターフェースでインフラを隔離する |
| Next.js の骨格 | ページが1枚出る | データ取得をどこに置くか決める | サーバ/クライアントの境界とキャッシュ |
| テスト可能な切り方 | 純関数を切り出せる | 入出力をテストする | 境界にモックを置く |
| 失敗の扱い | エラーを握りつぶさない | 呼び出し側が分岐できる形で返す | 再試行してよい失敗かを決める |

## Recurring question forms

- 与えられた要件の最小実装を Go または Next で書き、層の境界を示す
- 与えられたコードの責務違反を指摘し、ファイルを分けて直す
- 動かない症状から、コンパイル/実行/配置のどこを疑うか手順を書く
- なぜその置き場所にしたかを後輩に3分で説明させる

## Retest triggers

- handler に業務ルールを置いてしまった
- ページコンポーネントにデータ取得と表示が混在し、分けられなかった
- エラーをログだけ出して呼び出し側に返せなかった
