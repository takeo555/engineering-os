# Category: AI（Drill専用）

## Role in Engineering OS

**Drill専用カテゴリ。Design 15分では出題しない。**

AI は知識の床を作る領域として位置付ける。生成AIパスポート → CCAO-F → CCAR-F の順に、フェーズごとに題材が変わる（[ROADMAP.md](../ROADMAP.md) 参照）。

## Daily quota

- 毎日 **3問**、30秒・単答
- 記録は正答率のみ（例: `drill_ai: 3/3`）
- 間違えた分野は `05-failures/drill-misses.md` に追記され、翌日3問中1問を類題に置き換える

## Phase 1 の題材（2026-09-14 〜 生成AIパスポート受験日）

GUGA公式シラバスの主要領域：

| 分野 | 例題形式 |
|---|---|
| 生成AIの仕組み | 「TransformerのAttentionの役割を一言で」 |
| モデルの種類 | 「LLMとSLMの主な違いは」 |
| 学習手法 | 「ファインチューニングとRAGの使い分けは」 |
| リスク | 「幻覚が起きる主な原因は」「著作権侵害となる典型ケースは」 |
| 秘密情報 | 「プロンプトに載せてはいけない情報の代表例を1つ」 |
| バイアス | 「学習データバイアスの1例を」 |
| 法制度 | 「EU AI Actの高リスクAIの例を1つ」 |
| ガバナンス | 「生成物の商用利用で確認すべき点を1つ」 |
| 業務利用 | 「社内利用ポリシーで最低限定めるべき項目を1つ」 |

## Phase 2以降

Phase 2（CCAO-F期）以降は [ROADMAP.md](../ROADMAP.md) を参照。試験官は出題前に ROADMAP.md を読み、今日のフェーズに合う題材を選ぶ。

## Miss handling

- ドリルで間違えた問題は `drill-misses.md` に「日付・AI・分野・問題テーマ」の1行で記録される
- 翌日の AI ドリル3問のうち1問を、同じ分野の**別問題**に置き換える（同一問題の再出題ではない）
- W番号は振らない。Weakness Log には登録しない

## Retest triggers（Drillに再度出す条件）

- 同じ分野で連続2回間違えた → 翌週の AI 題材選択時に優先度を上げる
- 特定の分野を1週間触れていない → その分野を1問混ぜる

## Design側には出さない

生成AIの設計・評価・運用は、将来的に Code Review Track の題材として扱う可能性はあるが、**Phase 1〜3では出題しない**。集中を分散させないため。
