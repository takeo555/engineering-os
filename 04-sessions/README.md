# Daily Sessions

毎日、**Drill 8問（30秒・単答・合計4分）** と **Design 1問（15分）** をこの順でやり、その日のうちに完結させます。

## Directory

```text
04-sessions/
├── templates/
│   └── daily-session.md      … 保存後のセッションファイルの形（出題時の記録ブロックは `prompts/record-block.md`）
└── daily/
    └── 2026/
        └── 2026-09-03.md     … 1日1ファイル
```

ファイル名は`YYYY-MM-DD.md`。年ディレクトリで区切ります。

## Daily flow

| Time | Actor | Action |
|---|---|---|
| 03:10 | GitHub Actions（build-context） | `TODAY.md` を再生成（Design の Track/Format/Level と狙う弱点、Drill 8問の題材枠を決める）。05:40 に予備実行 |
| 07:00 | Project内の定期タスク | `TODAY.md` を読み、**Drill 8問をまとめて出して待つ** |
| — | You | iPhoneで Projects → 試験官 → 最新チャット を開く |
| 約4分 | You | 回答をまとめて貼る |
| — | Claude 試験官 | Drill 正誤判定、1行フィードバック、続けて Design 15分問題を出題 |
| 約15分 | You | 解く。終わらなくてもその時点で止めて回答を貼る |
| — | You / Claude | 必要ならヒント |
| — | Claude 試験官 | 30秒サマリ→詳細レビュー→採点確定→**Drill と Design を統合した1つの記録ブロック**をチャットへ出力 |
| 約30秒 | You | 記録ブロックをコピーして投函口 Issue #1 へコメント |
| 自動 | GitHub Actions | 記録をコミット、drill-misses.md 追記、弱点の開閉、Scorecard更新、TODAY.md 再生成 |

**合計約20分**。Drill 4分 + Design 15分 + やり取りのオーバーヘッド1分。

記録ブロックは**自分で** Issue #1「📥 記録の投函口」へコメントとして貼ります。claude.ai の GitHub 連携は読み取り専用なので、試験官は投稿できません（試験官側も投稿を試みない設定にしてあります）。新しいIssueは作りません。手順は [10-automation/inbox.md](../10-automation/inbox.md)。

問題文の「15分以内」は制約です。`time_spent_min` には Design に実際にかかった時間だけを書きます。分からなければ推測しません。

定期タスクの通知が届かなかった日は、Projectを開いて「今日の1問」と送れば同じことが起きます。この仕組みは通知が来なくても壊れません。

割り当てをどうしても取得できない日は、「おまかせ」と送れば曜日から決めた割り当てで出題されます。**0問で終わる日を作らないことを、割り当ての正確さより優先します。**

## Rules

- Drill と Design は必ず順番に、Drill を先にやる。Design から始めない
- Drill の全8問は一気に出題・一気に回答（1問ずつやらない）
- Design 15分で終わらなければ、その時点の回答を提出する
- Drill と Design の記録は1つの記録ブロックに統合される
- 回答は整形しない。考えた順のまま出す
- 分からなかった箇所は「分からない」と明記する（そこが翌日の出題材料）
- 課題を翌日へ持ち越さない。持ち越すのは弱点だけ
- 1日に2問以上やらない。埋め合わせをしない
- ヒントで補えた重要な観点は、最終回答として正しくても弱点として残す
- その日は記録ブロックを投函口へ出すまで終了しない

## Problem formats

| Format | 出題の型 | 評価の重心 | 回答環境 | モード |
|---|---|---|---|---|
| Recall | 単答式の基礎問題 | 正誤の即答性 | どちらでも | Drill |
| Design | 要件から設計を書く | 構造の妥当性と根拠 | キーボード | Design |
| Review | 与えられた設計/コードの問題点を指摘 | 指摘の的確さと優先順位 | どちらでも | Design |
| Debug | 症状から原因を切り分ける | 手順の順序と確認方法 | モバイル可 | Design |
| Explain | 実務で説明できるレベルで言語化 | 正確さと簡潔さ | モバイル可 | Design |

Recall は Drill 専用の Format です。`format_weights` のローテーション対象ではなく、毎日必ず8問出ます。

`eos.config.json` の `keyboard_days`（既定: 月・水・金）はDesign / Review、それ以外の日は散文で答えられる形式が出ます。スマホで15分DDLを書く朝を作らないための設定です。

## 記録の読み方

朝は**30秒サマリだけ**読めば十分です。スコア、いちばん重い抜け3件、再テストの合否が出ます。詳細レビューと参考解答は記録ファイルに保存されるので、夜に読み返してください。
