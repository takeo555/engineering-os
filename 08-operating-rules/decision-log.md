# Decision Log

構造・目的・運用ルールを変えた理由を残します。日々の学習内容は書きません。

## Template

```markdown
## YYYY-MM-DD — <決定>

- **背景:** 何が問題だったか
- **決定:** 何をどう変えたか
- **代替案:** 検討して採らなかったもの
- **代償:** 何を失うか
- **見直し条件:** どうなったら再検討するか
```

## 2026-09-02 — Engineering OSを開始し、English OSと同じ運用モデルを採用する

- **背景:** エンジニアリングの学習が読書と断片的な調査に留まり、設計判断の練習と記録が残っていなかった。
- **決定:** English OSと同じ構造（North Star / Skill Map / Tracks / Banks / Sessions / Failures / Reviews / Scorecard / Operating Rules）を採用し、1日完結型の設計問題を毎朝07:00に自動出題する。Repositoryを正本とし、ChatGPTを出題者・試験官とする。
- **代替案:** 書籍の輪読、資格試験の学習計画。いずれも「設計を自分で書く」練習量が確保できないため却下。
- **代償:** 毎日30分の固定枠を確保する必要がある。出題品質がプロンプトに依存する。
- **見直し条件:** 3か月時点で平均スコアが伸びていない、または30分内完了率が50%を切り続ける場合。

## 2026-09-02 — GitHub書き込みはActionsブリッジで行う

- **背景:** ChatGPTのGitHubコネクタは読み取り専用で、コミット・プッシュができない。dev-modeのカスタムMCPコネクタは書き込み可能だがBusiness/Enterpriseプラン・Web限定で、モバイルから使えない。ChatGPTの定期タスクはGPTsを使えない。
- **決定:** 3層に分離する。(1) 出題はGitHub Actionsのcronが生成しRepositoryへ保存、(2) 通知はChatGPT定期タスクがGitHubコネクタ（読み取り）で問題を読んで出題、(3) 保存は試験官GPTのActionが`repository_dispatch`を叩き、Workflowがコミットする。
- **代替案:** 全てをGitHub Actionsで完結（チャットの対話性を失う）／全てをチャットで行い記録を手動コピー（手動が残る）。
- **代償:** ChatGPT側に定期タスクとカスタムGPTの2つを設定する必要がある。GPT ActionsのためにGitHub PATを1つ発行する。
- **見直し条件:** ChatGPTの標準GitHubコネクタが書き込みに対応した場合、または定期タスクがカスタムGPT/MCPを使えるようになった場合。

## 2026-09-02 — レビューを受けて自動化の欠陥を修正する

- **背景:** 初版を多角的にレビューしたところ、次の欠陥が見つかった。(1) 弱点をClosedへ移すコードが存在せず、`weakness-log.md` が永久に膨らみ、弱点駆動の出題が機能しなくなる。(2) 週次と日次が同じルールで難易度を判定し、悪い週の翌週に2段落ちる。(3) LLM生成タイトルをWorkflowの`run:`にシェル展開していた（破損とスクリプト注入の経路）。(4) `git commit`に変更なしのガードがなく、週次が赤くなる。(5) Actionsのcron遅延に対し出題06:55と通知07:00でバッファが5分しかない。(6) LLM採点が月をまたいでドリフトし、Scorecardが時系列で比較できない。(7) Bankが自動更新されず、`promote_to_bank`が文字列のまま消える。(8) Monthly Reviewが未実装。
- **決定:**
  - 弱点に再テスト合否（`retests`）を導入し、`passed`はClosedへ移動、`failed`は優先度+1で3日後に再テスト。再発は類似判定で重複登録せず優先度を上げる
  - `base_level`を書き換えるのは週次のみ。日次は空白期間による一時的な引き下げだけを行う。週次の判定はコード側で決定論的に行い、LLMには任せない
  - Workflowの`run:`から`${{ }}`によるLLM生成テキストの展開を全廃し、ファイル経由に統一
  - 全Workflowに`git diff --cached --quiet`ガードとpushリトライを追加
  - 出題を06:30へ前倒し。加えて試験官GPTに`dispatchDailyProblem`を持たせ、未生成なら自分で起動できるようにした
  - `07-scorecard/anchors.md`（50/70/85点の見本）を作成し、試験官GPTのKnowledgeとして毎回参照させる
  - Bank昇格は`promotion-queue.md`へ自動で積み、週次で採否を判定し、書き写しは手動のまま残す
  - `monthly-review.yml`を追加
  - `session_days`と`keyboard_days`を設定化。曜日で出題形式を切り替え、スマホで長いDDLを書く朝を作らない
  - `STATUS.md`を自動生成し、連続実施・平均点・期限切れの弱点を1画面で見られるようにした
  - 週次レビューを日曜21:00へ移動（English OSの日曜20:00と衝突していた）
  - 未回答のまま残ったIssueを翌出題日に自動クローズ
  - `09-foundation`に実機確認の枠（週1回20分）を追加
- **代替案:** Bankへの自動書き込み（質が落ちるため却下）。難易度判定をLLMに任せる（再現性がないため却下）。全セッションをGPT内に閉じて通常チャットの定期タスクを廃止（プッシュ通知を失うため却下）。
- **代償:** 設定項目が増えた。試験官GPTのInstructionsが長くなり、指示の遵守率が落ちる可能性がある。PATにActions: write権限が必要になった。
- **見直し条件:** 1か月運用して、弱点のOpen件数が15件を超え続ける場合、または`retests`が送られない日が週2回以上ある場合。

## 2026-09-06 — 会社のChatGPT Business Freeワークスペースで運用する

- **背景:** カスタムGPTは個人アカウント（Free / Go / Plus / Pro）では作成できず、Business / Enterprise / Eduのワークスペースが必須であることが判明した。試験官GPTのActionsが唯一のGitHub書き込み経路なので、個人アカウントをいくら課金しても本構成は成立しない。会社には ChatGPT Business Free（¥0・早期アクセス枠）のワークスペースがあり、機能一覧にカスタムGPTが含まれている。また、本取り組みは会社から託されたタスクであり、記録が会社の管理下に入ることは要件と整合する。
- **決定:**
  - 会社のBusiness Freeワークスペースで試験官GPTを作る
  - スマホのChatGPTアプリは会社アカウントでサインインする。個人アカウントは削除せず残す（個人メールはドメイン制限でワークスペースへ招待できず、データ移行の選択肢自体が存在しないため）
  - PCのWeb版ではアカウント切替で個人と会社を併用する（モバイルは未対応）
  - **GitHubコネクタに依存しない設計にする。** コネクタは読み取り専用な上、Business Freeでの可否が公開されていない。試験官GPTのActionsが直接Issueを読むため、コネクタが無くても全機能が動く
  - **朝の通知の既定をGitHub Mobileにする。** ChatGPT側の機能（定期タスク・コネクタ）の可否に依存せず確実に動き、通知に問題全文が載る。定期タスクが使えるなら併用してよい
- **代替案:** 個人アカウントをPlusに課金（GPT作成不可のため却下）。有料Business 2席・月$40〜50（Freeで足りる間は不要）。採点をActions側へ移しChatGPT依存をゼロにする案（会社から託されたタスクの要件が「ChatGPTを講師・試験官にすること」であるため却下。ただしBusiness Free終了時の移行先として保持する）。
- **代償:** スマホのChatGPTが会社アカウントになり、個人利用も会社ワークスペースの記録として残る。個人の履歴は移行できず、見るにはログアウトが必要。Business Freeは公式に案内のない枠のため、終了・有料化のリスクがある。
- **見直し条件:** Business Freeが終了または有料化した場合。その時点で(1)有料Business 2席へ移行、(2)手動フォールバック、(3)採点をActions側へ移設、の3択から選ぶ。**記録はすべてGitHubにあるため、いずれの場合も学習資産は失われない。**

## 2026-09-06 — 個人の無料プランへ切り替え、書き込みをIssue貼付に一本化する

- **背景:** 前項でBusiness Freeワークスペースを前提にしたが、運用を個人アカウントの無料プランで行う方針に変わった。無料プランでは**カスタムGPTを作れず、GPT Actionsも使えない**ため、ChatGPTからGitHubへ書き込む経路が存在しない（コネクタは読み取り専用）。一方で調べたところ、**Projectsは無料でも使え（指示欄＋ファイル5個）、定期タスクも無料で使える**（3個まで・1日1回・時刻は枠指定・Projectのファイルは読めない・GitHubイベントトリガーは有料のみ）ことが分かった。
- **決定:**
  - **試験官はカスタムGPTではなくProjectで常設する。** Knowledgeに `anchors.md` / `examiner-manual.md` / `record-block.md` を置く
  - **書き込みは「記録ブロックをIssueに貼る」の一手に一本化する。** `issues: opened/edited` で `record.yml` が発火し、パースしてコミットする。PATもOpenAI APIキーも不要になった
  - **出題の割り当て（Track / Format / Level / 狙う弱点）はActionsが決め、問題文だけをChatGPTが書く。** ChatGPTに選ばせると弱点の再テストが放置されるため。決定は `CONTEXT.md` に書き、ChatGPTが毎朝読む唯一の入り口とする
  - **Repositoryをpublicにする。** コネクタの可否に依存せず raw URL で読めるようにするため
  - 週次・月次はActionsが数字だけを `WEEKLY_CONTEXT.md` / `MONTHLY_CONTEXT.md` に出し、講評はChatGPTが書いて同じくIssueで保存する
  - 実施ペースを平日5日から毎日へ変更する
- **代替案:** Plusに課金してカスタムGPT + Actionsを使う（コピペは消えるが月額が発生）。出題もActions + OpenAI APIで生成する（月数百円と、APIキー管理が増える）。定期タスクの中で採点まで行う（`anchors.md` を読めず点数がドリフトするため却下）。
- **代償:** 1日1回15秒のコピペが残る。無料枠の上限に当たると軽いモデルに落ちるため採点のブレが有料より大きい。添削の往復を1回に抑える必要がある。Repositoryが公開されるので、会社・顧客の情報は一切書けない。
- **見直し条件:** Plusへ課金した場合（カスタムGPTのActionsで書き込みを自動化すればコピペが消える。Repository側の変更は不要）。または、記録ブロックの貼り忘れが週2回以上になった場合。

## 2026-09-07 — 知識は材料、レビューは行き先。今期は基礎を厚くする

- **背景:** 技術知識がまだ拙く、設計判断の材料が足りない。一方で Mission の「知識は目的ではない」は「今は増やさなくてよい」と読めてしまい、基礎を厚くする判断と衝突していた。また「レビューを通し」は自分の案が通る側だけで、他人の設計を指摘できることが行き先として明示されていなかった。
- **決定:**
  - Mission を「足りなければ先に埋めるが、使えて初めて得たものとする」に直す。知識習得を到達点の隣には置かない
  - Explainability に、渡された設計を指摘して直せることを追加する（実務のレビュー担当は今期の出口にしない）
  - Current horizon（2026-09-07 – 2026-12-06）を North Star 末尾に置く。今期は DB 周辺の基礎を説明と指摘で使えるようにする。出口は W001 / W002 の30秒説明、スキーマの問題3つの指摘と修正、翌サイクルの Design 1問
  - 出題を基礎期間に合わせ、`base_level` を L1、Format 比重を Review / Explain 寄りにする。採点軸と `anchors.md`、試験官の「暗記問題を出さない」は変えない
  - Foundation は今期だけ週2〜3回まで増やし、W001 / W002 の実機確認を前倒しする
- **代替案:** 知識習得を Mission の到達点に並べる（「まだ拙いからインプット」が終わらなくなるため却下）。4 Track 同時に基礎からやり直す（重点が散るため却下）。試験官マニュアルと配点を基礎用に書き換える（期間が終わったあとの点数と比較できなくなるため却下）。
- **代償:** L2 の設計を書く量がしばらく減る。週次の自動昇格（直近5回平均85）が条件を満たすまで L1 に留まる。
- **見直し条件:** Current horizon の出口を満たしたとき、または 2026-12-06 の四半期見直し。平均が85を超えて週次が L2 に戻した場合も、Horizon の出口（説明・指摘・次の Design）は別途確認する。

## 2026-09-08 — Horizon を月次にし、Track を6本にする

- **背景:** 90日の Horizon だと、コーディングが先か DB が先かが月の途中で変わっても出口を切り替えられない。分類も設計4本だけでは、実装と生成AIの練習が OS の外に落ちる。
- **決定:**
  - Current horizon は毎月見直し。翌月は月次レビューまで書かない。Mission は変えない
  - 2026-09 の出口は Layered Architecture と Coding（Go / Next.js）。AI は Track として追加するが、今月の出口にはしない
  - Track を6本にする: 既存4 + `Coding / Go / Next.js` + `AI / LLM`。毎週6本全部は出さない。`horizon_tracks` だけ週内補完する
  - Foundation の今月キューを Go / Next の起動に差し替える。W001 / W002 は弱点ログに残し、期限が来たら日次で出る
- **代替案:** コーディングを Foundation だけに置き Track にしない（今月の出口にしたいため却下）。AI を知識暗記 Track にする（Mission の「使えて初めて得た」に反するため、レビューと判断の Track にした）。North Star の Mission から作り直す（行き先は変わっていないため却下）。
- **代償:** 日次30分にコードを書く回が増え、設計量は減る。DB 弱点の再テストは期限到来時に Horizon を食い、散ることがある。
- **見直し条件:** 9月末の月次レビュー。Coding のセッションが2回に満たない、または Architecture の指摘が「なんとなく違う」で止まっている場合は、10月の Horizon で片方に絞る。

## 2026-09-08 — AI Track の10月出口は生成AIパスポート合格

- **背景:** AI の学習の当面の目標は、2026-10 の生成AIパスポート合格。レビューと判断の Track として足したままだと、9月の日次に混ざるか、試験勉強が OS の外に落ちて見えなくなる。
- **決定:**
  - 10月の AI Track 出口だけ先に固定する。Horizon の他の項目（Coding を続けるか等）は9月末に決める
  - 合格は知識の床であり、AI Track の到達点ではない。合格後は生成結果のレビューに戻す
  - 2026-09 は `track_weights` の AI を 0 にし、日次の1問にしない。試験勉強は30分枠の外
- **代替案:** 9月からパスポート範囲を日次 Explain にする（今月の Coding / Architecture が削れるため却下）。パスポート合格を Mission や Track の最終到達にする（知識の増加を到達と呼ぶことになるため却下）。
- **代償:** 9月は AI の記録が scores に残らない。10月は試験対策の Explain が増え、設計問題の密度が下がる。
- **見直し条件:** パスポートの合否が分かった時点。合格なら L2（出力レビュー）へ。不合格なら翌月も L1 を出口にするか、やめかを月次で決める。

## 2026-09-08 — CONTEXT→出題→採点→記録の状態を SESSION で凍結する

- **背景:** CONTEXT は DB / Review / L1 / W001 なのに Layered Architecture / Design / L2 が出た。採点・記録が「いまの CONTEXT」を読み直すと、出した問題とメタデータがずれる。記録フェンスの `text` や `id=` で Importer が落ち、anchors 無しでも採点が通っていた。
- **決定:**
  - 出題直前の CONTEXT を SESSION として凍結し、採点・記録はそれを正本にする
  - 必須キー欠落は Importer が拒否し、不足キーを返す。フェンス属性は無視して読む
  - 採点前に anchors.md と examiner-manual.md が取れなければ採点しない（試験官指示 + コードの判定）
- **代替案:** Importer だけ直す（出題の取り違えは残るため却下）。
- **代償:** 必須キーが無い記録は scores に入らない。直し貼りが必要。
- **見直し条件:** 同じ取り違え（CONTEXT と出題の Track 不一致）が再発した場合。
